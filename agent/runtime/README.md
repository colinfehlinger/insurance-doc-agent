Step 3 of the series. Goal was deliberately small: **stand up one minimal
AgentCore Runtime and invoke it once**, to prove the loop before any real tools
exist. No BDA, no DynamoDB, no matter state, none of the five real tools —
hello/echo level only.

At the time, the fixed pipeline (`infra/`) was untouched by this, and
`infra/lib/agent-stack.ts` was an SSM placeholder. (As of Step 6 that stub is now
the real agent stack.)

## ⚠️ Pinned CLI version — do not float

```
@aws/agentcore  0.24.1     <-- pin. NOT `latest`, NOT `@preview`.
```

Generated by `@aws/agentcore@0.24.1` (published 2026-07-13) on 2026-07-21.

npm carries a **`preview` dist-tag at `1.0.0-preview.22`** — a 1.0 is in
flight. Installing `@latest` or `@preview` between sessions can regenerate this
project with a different config schema and break a deploy that worked
yesterday. Reinstall the exact version if the machine changes:

```bash
npm install -g @aws/agentcore@0.24.1
agentcore --version   # must print 0.24.1
```

**Tracked series task:** migrate to `@aws/agentcore` 1.x once it goes stable.
Expect config-schema churn in `agentcore/agentcore.json`; re-run `agentcore
validate` after upgrading and diff the generated `cdk/` before deploying.

```
agent/
  system-prompt.md          the real Document-Chase prompt (Step 6+, unused here)
  tools/README.md           the five real tools (Step 6+, unused here)
  runtime/
    IdaAgentProbe/          <-- the CLI creates a <project-name>/ dir; this
      agentcore/                nesting is the CLI's, not a choice
        agentcore.json      project + runtime config
        aws-targets.json    account + region  (see caveat below)
        cdk/                CLI-emitted CDK app -- deploys via `agentcore deploy`
      app/IdaAgentProbe/
        main.py             Strands agent entrypoint
        model/load.py       Bedrock model binding
```

`infra/` and this sub-project have **separate deploy paths and separate
lifecycles**: `infra/` deploys with `npx cdk deploy --all -c stage=dev`; the
probe deploys with `agentcore deploy`. Nothing is shared. That is deliberate
for a throwaway probe.

## Model — Nova Micro (probe only)

`app/IdaAgentProbe/model/load.py` pins:

```python
MODEL_ID = "us.amazon.nova-micro-v1:0"
```

Amazon Nova Micro via the `us.` cross-region inference profile. Verified
`ACTIVE` in us-east-1 and confirmed invokable — a live `bedrock-runtime
converse` returned `stopReason: end_turn` in 696ms. There is **no `global.`
variant** for Nova Micro; `us.` is the only published prefix.

**Why not the scaffold default.** `agentcore create` hardcodes
`global.anthropic.claude-sonnet-4-5-20250929-v1:0`, which is a generation behind
current Bedrock Claude *and* is gated behind an Anthropic use-case access form
in this account — that gate blocked the first invoke outright. Nova Micro has no
such gate, is ~100x cheaper ($0.035/$0.14 vs $3/$15 per MTok), and is faster on
the smoke test.

**This is a probe-only choice.** Step 3 proves the toolchain loop, not model
quality — the probe does no real tool selection and reasons over no matter
state. **The production model is deliberately undecided**; reliable tool-calling
is the real agent's entire job, and small models are typically weakest exactly
there. Evaluation criteria are in
[ADR-001](../../docs/decisions/ADR-001-foundation-model.md) and run in Step 5.

## Local state — not committed

`agentcore/.cli/deployed-state.json` is **local state, regenerated by
`agentcore deploy`**. After a successful deploy it holds the AgentCore Runtime
and IAM role ARNs, which embed the 12-digit account id — the same leak class as
`aws-targets.json`.

The generated `agentcore/.gitignore` *force-commits* it via an explicit negation
(`!.cli/deployed-state.json`) so teams can share deployed ARNs. The root
`.gitignore` overrides that by excluding the **directory** (`agent/**/.cli/`) —
a file-level rule there would lose, because a deeper `.gitignore` takes
precedence over a parent, and a file under an excluded directory cannot be
re-included.

Nothing is lost by ignoring it: re-run `agentcore deploy` and it is rebuilt.

## ⚠️ `aws-targets.json` hard-codes the account id

The `AwsDeploymentTarget` schema requires `account` to match `^[0-9]{12}$` — it
accepts no token or env-var indirection. This **conflicts with the project rule
that no account id is committed** (`infra/` resolves it from
`CDK_DEFAULT_ACCOUNT` at synth time).

The file is therefore **gitignored**; `aws-targets.example.json` is tracked in
its place. **On a fresh clone, regenerate it by copying the example and
replacing the placeholder `000000000000` with your own 12-digit account id:**

```bash
cd agentcore
cp aws-targets.example.json aws-targets.json
# then edit "account" -> your 12-digit AWS account id
```

Without it, `agentcore deploy` fails with
`No deployment targets configured. Please define targets in agentcore/aws-targets.json`.

This is one input to the later architecture call below.

## Open architecture question — deliberately unresolved

`agentcore deploy` runs **CDK under the hood** (it supports `--diff`, which
prints a CDK diff), and the CLI emits its own `cdk/` app depending on
`@aws/agentcore-cdk` (currently `^0.1.0-alpha.19` — an **alpha** L3 construct
library) plus its own `aws-cdk-lib ^2.248.0`, separate from the root project's
pinned `2.261.0`.

Whether that generated `cdk/` eventually folds into `infra/` as a construct, or
stays a referenced sub-project deployed separately, is a **later** call. Inputs
so far: the alpha L3 dependency, the duplicate `aws-cdk-lib` version, the
hard-coded account requirement, and the fact that regenerating the project
overwrites hand-edits to `cdk/bin/cdk.ts`. Not resolving it now.

## Cost

Runtime billing is **consumption-based with no idle charge**: $0.0895/vCPU-hour
and $0.00945/GB-hour, metered per second on actual CPU and peak memory, 1-second
minimum. AWS states "I/O wait and idle time is free."

With `memory: none` (no $0.25/1,000 events), no Gateway (no $0.005/1,000
invocations), and `CodeZip` (no ECR image storage), a deployed-but-uninvoked
runtime costs approximately nothing. **There is no need to tear it down after
proving the loop** — a handful of invokes will cost fractions of a cent against
the $25 budget, and Step 6 builds on the same runtime.
